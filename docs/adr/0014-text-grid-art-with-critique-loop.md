# 0014: Model-generated art through text grids with a validate/render/critique loop

Status: accepted
Date: 2026-09-20

## Context

v0's sprites were generated by a language model as raw character grids, one full-screen frame
per walk position, with no validation. The result was incoherent. Current models are much
better at generation, and the user wants to keep them in the loop. The failure was as much
missing tooling as model quality.

## Decision

Sprites are authored as 16x16 text grids, one pose per drawn frame, with motion procedural in
the core. `spritekit gen` runs generate -> validate -> render to an OLED-look PNG -> vision-model
critique -> revise, with candidates for the anchor pose and diff bounds against it for the
others. Image models supply concept art and, through a crop/box-resize/threshold pipeline, seeds
and splash screens. A human approves contact sheets; approvals are hashed in `approved.lock`.

## Consequences

- Fifteen required drawn frames per species instead of dozens.
- The validator encodes the style guide as numbers, so most bad output is rejected before a
  critic call is spent.
- Tooling is Python and offline; nothing model-related ships in the core.
- If models improve further, only the prompts change; the format and validator stay.
