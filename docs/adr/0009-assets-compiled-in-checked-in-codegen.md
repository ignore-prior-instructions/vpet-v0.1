# 0009: Assets compiled in via checked-in codegen

Status: accepted
Date: 2026-09-20

## Context

Sprites and species tables could be loaded at runtime by hosts, generated at build time by a
`build.rs`, or generated by a tool and checked in.

## Decision

`spritekit compile` (Python) emits `crates/vpet-core/src/assets/generated.rs`, which is checked
in. CI runs `spritekit compile --check` to keep it fresh. Species ids come from an append-only
registry. `content_hash` over the generated tables is embedded in the build and every save.

## Consequences

- `cargo build` for native, wasm32, and ESP32 never needs Python.
- Art changes appear as Rust diffs in review, next to the text-grid diffs.
- Runtime asset loading is not possible; hot preview is provided instead through a
  `dev-overrides` feature that overlays poses in memory.
- A content change is a rules change and is visible in the save header.
